Read the readme.md file within this skill, and explore the other available files.
If creating visual artifacts (slides, mocks, throwaway prototypes, etc), copy assets out and create static HTML files for the user to view. If working on production code, you can copy assets and read the rules here to become an expert in designing with this brand.
If the user invokes this skill without any other guidance, ask them what they want to build or design, ask some questions, and act as an expert designer who outputs HTML artifacts _or_ production code, depending on the need.

Rules of thumb: HelveticaNeue 400 for words, `--font-mono` (IBM Plex Mono) for every figure, `--font-mono-detail` (JetBrains Mono) for codes, paths and IDs, `--font-detail` (Helvetica Neue Condensed) for dense detail at 13px and below; scale 11 / 12 / 13 / 14 / 16 / 18 / 24 / 28 (Stat) / 40, tracked 0.011em except 11px uppercase at 0.3px; 4-based spacing (card pad 16, gap 12, gutter 24); page `--surface-sunken`, cards `--surface-card` with a `--border-card` hairline, no shadow, no radius on containers (buttons 6 / 4, labels 4); ink hairlines only for structure (rail, header); `--border-control` edges what you press or type into (outline buttons); `--text-muted` for hints and placeholders, `--text-faint` never for copy; every indicator a square; colour only for data (`--data-1…6`, `--delta-up/down`) and status (moss / slate / amber / brick / graphite); slate iris in chrome only as a fill (filled buttons, the accent card); it is also the in-progress status colour. Everything themes through tokens — never hard-code a hex; `[data-theme="dark"]` flips them.

Tool recipe (an editor rather than a dashboard): link `tools.css` after `styles.css` and use its vocabulary — `.app > aside + main`, `details.panel` sections, `.row` / `.slider` / `.seg` / `.check` at 28px, `.presets`, `.list > .item`, `.drop`, then `main > .topbar + .stage + .footer`. One `button.primary` per view. Selection is ink (filled segment, 2px marker, 2px edge), never colour alone. See `guidelines/controls-tools.html`.

Dashboard recipe: `AppShell ground="sunken" width="full"` with `ShellHeader` + `FilterBar` in the header slot → `StatGrid` of 4–6 `Stat`s (label / mono value / `Delta` / `Sparkline`, each with an onClick) → `CardGrid` of `Card`s holding `BarList`, `Progress` or a `DataTable`. Drill down four ways, one rule each: `Peek` on hover (never the only route), inline expand (`DataTable expandedKey + renderExpanded`) for a little more, `Panel` as `AppShell drawer` for a lot more, a full page with `Breadcrumb` when the thing has its own URL. Sparklines and bars only — no pies, legends or axes. Control geometry: height from padding, top = bottom + 4px (36 = 1 + 11/16/7 + 1, 28 = 1 + 8/14/4 + 1, 22 label = 1 + 5/14/1 + 1; the 18 uppercase tab is 4/12/2 with no border).
